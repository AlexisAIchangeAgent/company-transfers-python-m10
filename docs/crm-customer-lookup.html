CRM customer lookup page: what it does

Training material. Company Bank SA, its customers and its figures are invented (crm/customer-lookup.html:1,30).

The page crm/customer-lookup.html is a static page of the internal CRM (README.md:201; CLAUDE.md:39). A user types a name or a customer ID, picks a customer, and reads the transfer history of that customer. This page is for a developer who must test or change it. Every statement cites a file and a line; paths are relative to the repository root. ASSUMPTION marks something that is not verified from the repository. MISSING marks information the repository does not contain. Both lists are repeated in section 7.

Important: the page is not a client of the fee service. It has no fetch, no XMLHttpRequest and no URL (searched in crm/customer-lookup.html; the script is inline, lines 48-131). The customers, the transfers and every fee are typed in the file (lines 50-74). A change of fee rule in src/company_transfers/domain/fees.py does not change what this page shows.

3. What the page does

  • Search: the query is trimmed and lower-cased, and a customer matches if the name or the ID contains it, in any case (crm/customer-lookup.html:109-112). An empty query matches the three customers.
  • Each search clears the list and hides the history panel (lines 113-114). "No customer found." is shown when nothing matches (line 115).
  • A click on a customer row shows the history of that customer, in the order of the array, which is newest first in the data (lines 91-106, 54-71).
  • The history title is "<name> (<ID>) - transfer history" (line 92). The result list also shows the segment (line 122); the history does not.
  • Amounts and fees are text. Amounts have thousands separators, for example 2,000.00 (line 54); fees have two decimals (lines 54-71).
  • Rows of the list are li elements with a click handler and no tabindex (lines 117-125): a click opens a history, the keyboard does not. ASSUMPTION a browser gives no keyboard focus to such an element; not tested here.
  • Each history row gets the class "w" + t.type.length (line 96), so w8 for standard and w7 for instant. No CSS rule uses it (lines 9-25). MISSING the purpose of these classes.

  • No package, no external script, no stylesheet link, no web font, no image: styles are inline (lines 8-26) and so is the script (lines 48-131).
  • No network call, and no storage (searched for fetch, XMLHttpRequest, localStorage and http: no match).
  • Browser: the script uses replaceChildren (lines 93, 113), const, arrow functions and for...of. ASSUMPTION a current browser runs it; the supported browsers are not stated and I did not open the page.
