Transfer-fee service: how to call it

Training material. Company Bank SA, its customers and its figures are invented (README.md:3).

The service computes the fee of a customer transfer before the customer confirms it (README.md:5). Every statement below cites the file and line it comes from. Paths are relative to the repository root. ASSUMPTION marks something that is not verified from the repository. MISSING marks information the repository does not contain. The lists are repeated in section 8.

Not used as a source: docs/README-service.md. It is out of date (README.md:168-170): it lists GET /fees/{id}, a maximum fee of 40.00 and bankers rounding, and none of this is in the code.

3. Endpoints

3.1 GET /health

Returns 200 {"status": "ok"} (api/routes.py:22-24; tests/unit/test_api.py:15-19). It does not call the exchange-rate provider.

3.2 POST /fees

Defined at api/routes.py:27-43. The body is JSON.

FieldRuleSource
amountDecimal, greater than 0, at most 2 decimals. In tests/unit/test_api.py 0, -5.00 and 10.001 give 422.api/schemas.py:12; tests/unit/test_api.py:54-56
currency"MDL" or "EUR"api/schemas.py:13
type"standard" or "instant"api/schemas.py:14
customer_segment"retail" or "premium"api/schemas.py:15

All four fields are required (a body without amount gives 422, tests/unit/test_api.py:59). The repository sends amount as a JSON number (tests/unit/test_api.py:23) and as a string (run-local.ps1:122). ASSUMPTION both are accepted by pydantic; the string form is used by run-local.ps1, which prints the answer, and I did not run it.

Response, 200: {"fee": <number>, "currency": "MDL", "rule": "<string>"} (api/schemas.py:18-21). The fee is always in MDL (schemas.py:20) and is written with two decimals, for example "fee": 10.00 (tests/unit/test_api.py:33-36). If your client parses JSON numbers as floats, parse them as decimals: the repository's own tests use parse_float=Decimal (tests/unit/test_api.py:8).

4. Fee rules as implemented

CaseRule in the codeSource
Standard, MDL0.5% of the amount, rounded half up to 2 decimals, minimum 5.00, maximum 50.00domain/fees.py:17-19,34-35

Examples, taken from the tests and the feature file, not from a running service:

  • MDL 2000.00, standard, retail: fee 10.00, rule standard-mdl (tests/unit/test_api.py:22-30).
  • MDL 2000.00, instant, retail: fee 20.00 (features/instant-fee.feature:24).
  • MDL 2000.00, instant, premium: fee 10.00 (features/instant-fee.feature:28-31).
  • EUR 500.00, instant, retail, rate 19.8765: fee 59.69 (features/instant-fee.feature:44-47).

The service uses only the rate field of the provider answer; as_of is parsed (clients/exchange_rate.py:57) but not used (domain/fees.py:63). A rate is requested for every EUR transfer; no cache is in the code (domain/fees.py:62-64).

Known conflicts

  • EUR rounding. The published tariff says the converted amount is not rounded and the fee is rounded half up (docs/fee-rules.md:16-17). The code truncates the converted amount (domain/fees.py:64) and rounds the fee half even (domain/fees.py:53). The two can differ by 0.01. This is an open dispute (README.md:165-167; incidents/INC-2026-0412.md). MISSING the decision on which rounding is correct (CLAUDE.md, section 3).
  • The instant fee is not in the published tariff (docs/fee-rules.md:22). Its rules come from features/instant-fee.feature:7-11. MISSING the published instant tariff.
  • Instant transfer at night is not implemented. The feature expects 25.00 (features/instant-fee.feature:49-55) and the service charges 20.00. MISSING the definition of "night" and how the service learns the time.

6. Run it

Run every command from the repository root. Setup needs network access (README.md:39). The commands in this section come from README.md, Makefile and run-local.ps1. I did not start the service; I ran only the test commands of section 7.

6.1 Set up

Windows PowerShell, the script of the project (README.md:25), or by hand (README.md:63-66):

powershell -ExecutionPolicy Bypass -File .\step-3-setup.ps1

py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt

macOS Terminal (README.md:57-59):

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt

This installs the dev extra too (requirements-dev.txt, README.md:183), which includes tools you do not need to call the service.

6.2 Start it

Windows PowerShell (README.md:86), in the foreground:

.venv\Scripts\python -m uvicorn company_transfers.main:app --reload --port 8000

Or in the background, with a health check and one fee call (run-local.ps1:2-3,81-133):

.\run-local.ps1
.\run-local.ps1 stop

run-local.ps1 removes RATES_BASE_URL from its environment, so it always uses the fixed rate (run-local.ps1:94-95).

macOS Terminal (README.md:77; make run does the same, Makefile:13-14):

.venv/bin/python -m uvicorn company_transfers.main:app --reload --port 8000

Use the real provider: set the variable before starting. MISSING the provider's real URL.

6.3 Call it

In Windows PowerShell 5.1, curl is an alias of Invoke-WebRequest, so the macOS form does not work there (README.md:82). Windows PowerShell, from a second terminal (based on run-local.ps1:122-125):

$body = '{"amount": "2000.00", "currency": "MDL", "type": "instant", "customer_segment": "retail"}'
Invoke-WebRequest -UseBasicParsing -Method Post -Uri http://localhost:8000/fees -ContentType "application/json" -Body $body | Select-Object -ExpandProperty Content
Invoke-WebRequest -UseBasicParsing -Uri http://localhost:8000/health | Select-Object -ExpandProperty Content

macOS Terminal (README.md:78-79):

curl -X POST http://localhost:8000/fees -H "Content-Type: application/json" \
  -d '{"amount": 2000.00, "currency": "MDL", "type": "instant", "customer_segment": "retail"}'
curl http://localhost:8000/health

Expected answers, derived from features/instant-fee.feature:24 and tests/unit/test_api.py:19,33-36, not observed from a running service: {"fee": 20.00, "currency": "MDL", "rule": "instant-mdl"} and {"status":"ok"}. Port 8000 comes from the run command; MISSING the address of any shared or deployed instance.
